# Vanilla 基础战斗、居民命令与编队

[架构说明](architecture.md) · [English](../en/combat-architecture.md)

本增量从战斗初稿 `e40ebc7` 续作，当前已合入 master `7cf7259`。已提供可配置敌意、居民自卫与逃跑、服务端单人命令、实际 UnitGroup、编队巡逻，以及真实近战、弓和弩会话。可选 War 模块现提供框选与快捷编队输入；袭击、战略 AI 和枪械兼容仍未实现。

## 模块边界

| 模块               | 职责                                                                       |
| ------------------ | -------------------------------------------------------------------------- |
| Core               | 居民、劳动、物品所有权、生命周期、通用出行与互斥执行                       |
| Vanilla            | 日常敌对、自卫、巡逻、命令、实际小队、站位、具体行走及武器契约             |
| War                | RTS 框选、数字快捷选择组、鼠标命令与实时路径队列；袭击、战略 AI 等留待以后 |
| 独立枪械扩展，未来 | 通过 Vanilla 契约调用 TaCZ、Point Blank 各自的原生逻辑                     |

Core、Vanilla 不依赖 War 或枪械模组。Create、Cookery、Modular Golems 保持独立扩展。

## P0/P1：日常敌对与防御

`NativeHostility` 在服务端 EntityJoinLevelEvent 中只安装轻量 Goal，不查询世界。实际索敌延后到正常 AI tick，避免区块尚未 FULL 时查询世界。

- 为实现原版 Enemy 接口的怪物安装一个轻量居民目标；只有进入实体类型标签 `folkways:resident_enemies` 的类型才执行索敌。优先级不早于 6，且排在安装时的所有原生目标之后。移动、近战、射箭和苦力怕引爆继续由怪物原生 AI 执行。
- 排除 NeutralMob，避免继承 Zombie 的僵尸猪灵变成主动敌人；末影人保持原版中立语义。
- 通过 Bodies.of 和聚落身份筛选居民，兼容其他注册 ResidentKind。离籍、死亡和移除会结束追击。
- 重复进入不累加 Goal；NBT 重载的新实体重新安装。测试包含自动发现、实际追击和伤害、两类怪物重载，以及原版村民目标。
- Threats.hostile 供巡逻和实际打击共用，尊重同盟与中立怪物的当前愤怒状态。出手时再检查敌对资格和视线。
- 默认名单含僵尸和骷髅的原版变种、蜘蛛、洞穴蜘蛛与苦力怕。蜘蛛仅在原版亮度值低于 0.5 时主动索敌；明亮处未交战的蜘蛛也不被巡逻主动挑衅，已发生的战斗按原版攻击 Goal 脱离。
- 武装居民离岗后可反击 100 tick 内、12 格以内的怪物袭击者。生命不高于 35% 时，恐惧高于反击；巡逻继续复用 StrikeNode。
- 无武装居民沿用伤害或火焰触发的恐惧；袭击者仍在追赶时继续避险。安全点采用有用的距离增益，逃跑目标保持到抵达、失败或 120 tick 截止，避免随机采样为空时反复撤回。

### 可继承的敌意标签

1.21.1 的原版 `Enemy` 是 Java 标记接口，NeoForge 的通用实体标签没有提供等价的完整敌意名单。巡逻保留对 Enemy 实现的自动识别，数据包可使用以下实体类型标签补充或排除。

| 标签                                | 用途                                                             |
| ----------------------------------- | ---------------------------------------------------------------- |
| `folkways:resident_enemies`         | 允许已有原生攻击 AI 的 Enemy 类型主动索敌聚落居民                |
| `folkways:undead_resident_enemies`  | 被上一个标签引用的原版僵尸、骷髅变种名单                         |
| `folkways:patrol_targets`           | 巡逻的额外候选；默认继承 resident_enemies，已有 Enemy 仍自动识别 |
| `folkways:ignored_resident_enemies` | 优先排除 Folkways 附加索敌和巡逻主动攻击                         |

例如在数据包 `data/folkways/tags/entity_type/resident_enemies.json` 中追加自己的分类：

```json
{
  "values": [
    "#my_pack:hostile_undead",
    { "id": "my_mod:monster", "required": false }
  ]
}
```

标签可以嵌套引用，`replace: true` 可替换既有名单。每次尝试索敌及继续追踪均读取当前标签，`/reload` 对已加载实体生效，不额外叠加 Goal。中立状态、聚落居民身份与同盟检查仍然生效。标签不会补出没有的原生攻击动作；排除名单也不关闭原版反击或已经开始的苦力怕引线。

## P2：单居民命令与返岗

公共 API 位于 Vanilla 的 `plugins.combat.command.ResidentCommands`：

```java
var commands = ResidentCommands.of(colony);
var order = commands.hold(body, destination);
order.close();
```

| API         | 行为                                          |
| ----------- | --------------------------------------------- |
| move        | 到达后标记 ARRIVED，自动交还劳动控制          |
| hold        | 到达后驻守，等待解除；可指定朝向              |
| retreat     | 以更高优先级及 1.3 倍行进速度撤退，到达后驻守 |
| guard       | 保留阵位，允许战斗和恐惧安全抢占，结束后回位  |
| Order.close | 只解除该句柄，旧句柄不能取消新命令            |
| current     | 查询当前命令和 MOVING、HOLDING 等状态         |
| validate    | 只验证，不接管，供小队整批校验                |

API 要求可信服务端线程、真实聚落登记、已加载且未乘坐载具的 PersonBody，以及同 realm 内 128 格以内的已加载目标。战斗页在每次服务端操作时重新确认当前聚落管理权限，并在调用 API 前验证成员归属与目标范围。其他 ResidentKind 的命令支持需要单独验证。

命令复用 Core 现有 Urge → ColonyLabor → BodyRunner 安全中断流程。旧任务释放展示工具和出行后，同一个执行器开始命令；没有第二个导航控制器。解除后执行最新计划，不重放已撤销任务。Core 仅补充过期临时 Urge 拒绝记录回收，以及通用 `Node.directTravel()` 选项。该选项使用居民现有 Locomotion 走本地路径；普通劳动仍采用原有多方式出行规划。

命令不持久化。死亡、卸载、离籍和聚落关闭会释放控制；移动超过 1200 tick 也释放并标记 FAILED。驻守和已到达的撤退等待显式解除，期间可能压制日常需求。通过通用 `Node.staysAtWorkSite()` 约束，居民受推离开后由同一执行器重新回位。失败或旧存档句柄不代表有效控制权。

GUARD 让出同一执行器给恐惧或战斗时，不消耗移动计时；实际重新取得执行器后继续计时。从未取得执行器的命令仍保留有限等待上限。

## P3：实际 UnitGroup 与部署意图

`UnitGroups.of(colony).create(people)` 创建实际队伍，`ofResident(id)` 查询唯一归属。实际成员及存档加载不再截断为 8 人。转组解除旧队伍对该成员的控制。队伍 ID、成员顺序写入聚落账本；部署命令不持久化，重启后队伍恢复为 IDLE。

```java
var group = UnitGroups.of(colony).create(people);
group.move(new Deployment(left, right, front, new Deployment.Formation(2)));
```

Deployment 接收两个同高度、同 realm 的端点、与阵线近乎垂直的水平正面方向，以及 2～8 格间距。`Formation(spacing)` 保留单排横队；`Formation(spacing, columns)` 支持指定列数的多排阵位。端点线长仍不超过 128 格，各成员必须具有不同且安全的整数阵位。War 提交部署意图，无须逐 tick 操纵居民。

- move 按顺序让成员进入目标纵队，再恢复横队，避免后排先占位堵住前导成员。纵队阵位无站立空间时尝试直接横队。
- hold 直接建立横队；gather 在中心附近集合；release 解除全部成员命令。
- guard 建立可被战斗和恐惧安全抢占的站岗编队，使用真实 GUARD 命令并沿用队伍生命周期。
- retreat 通过实际队伍维护高优先级撤退命令，到达后驻守；其他有权管理聚落的玩家也可从战斗页解除，旧队伍句柄不能覆盖成员后来收到的个人命令。
- 单人新命令或单人解除会让该成员退出队伍控制，旧队伍不会覆盖新句柄。
- 死亡、离籍成员移出；卸载成员保留为 missing，现有成员重排；重新加载后分配新阵位。
- 无路可走时报告 FAILED 并释放全部成员，可在开路后重新提交。没有强制传送或无限重试。

四人单格开口与恢复横队是已验收的具体场景。新增紧凑多排尚需游戏实测，不保证所有瓶颈、任意地形、载具或舰船部署；单独的 16/32/64 总实体战斗采样不能推广为大编队性能保证。War 的快捷选择集可以重叠，实际队伍归属不能重叠。

临时纵列阵位可以在预定高度上下两格内寻找安全落脚点，最终横队仍要求精确站位。高度调整后的临时阵位不可达时，重新验证并尝试最终横队一次；最终横队仍不可达就失败释放。另有四人通过两次单格转弯及两级台阶、再返回巡逻的验收场景。

### 编队巡逻与主动交战

`group.patrol(List<Deployment>)` 接受 2～16 个同 realm 的部署点，循环执行纵列入场与横队重组。`patrolRoute()`、`patrolStop()` 和 `phase()` 提供观察；路线及交战状态不写入存档。

- GUARD 的权重为 1.5，健康交战为 2.5，恐惧为 2，显式撤退为 4。仍由同一 BodyRunner 交接，不增加战斗导航控制器。
- 携带可用武器的守卫无需先受伤即索敌；目标与交战阵位均限制在当前守卫槽 12 格内，避免无界追击。远程武器在有视线及射程内优先原地射击。
- 健康守卫短期续交战租约，队伍显示 ENGAGING、暂停路线与移动超时。低血战斗不续租，恐惧可以接管。
- 敌情解除后先返回本次阵位，现有成员全部归队并停留 20 tick 后再去下一站。死亡、失联、回归与单人撤退沿用真实队伍的成员处理。
- 队伍的 HOLDING 与停留计时同时检查实际成员位置；GUARD 被抢占后先回到 MOVING，不能用交战前缓存的到岗状态提前推进路线。近战站位预留导航到站容差，实际伤害仍检查原生距离和视线。
- 所有路线点先验证，再替换现有控制。不可达时 FAILED 并释放；全员失联时保留临时路线并 WAITING，重载后从当前站重新组队。

### 战斗页与点位配置

Vanilla 通过既有 Front 扩展接口，在殖民书注册独立 `folkways:combat` 战斗页。页面可以选择已加载居民、创建或选择实际队伍，从玩家脚下或服务端验证的瞄准支撑面添加点位，再显式执行。一个点配置站岗点，两个至十六个点配置循环巡逻；每个点是阵型中心，不是部署线的一端。

页面同时提供撤退、解除及近战／弓／弩偏好。每次操作在服务端重验管理权限；失效或其他聚落的队伍 ID、部署时失联的成员、无效地形和越界目的地均不能接管控制。含卸载成员的队伍仍可解除。点位草稿保留在当前服务端会话中，重启不会恢复运行命令。此页不增加 War 框选工具或快捷键。

### V 入口与个人相机设置

Core 提供 `RegisteringUi.tool(OverheadTools.Tool)`，供扩展声明独立的俯视工具、图标、相机偏好及开页动作。Vanilla 注册 `folkways:combat`，与点选、圈地、画线并列。未安装 War 时，右键或“队伍与命令”打开原有战斗页；安装 War 后，世界区域的左右键用于下述战斗操作，“队伍与命令”仍可打开站岗、撤退、解除和补给设置。关闭 V 清选区；仍在快捷组中的居民保留命令，无剩余引用者释放本轮 RTS 控制。

默认只有战斗工具使用新操作：中键拖动在水平面平移，Alt＋中键围绕视线焦点等距旋转。焦点由中心射线的实际碰撞确定，没有有效地面时使用有限距离回退；一次拖动锁定操作及焦点，中途改变 Alt 不切换手势。平移维持世界高度，当前未实现地形高度跟随或建筑避障。其他工具在默认设置下保留原有相机和修饰键行为。

书内设置和 NeoForge 模组配置页均提供“全局战斗视角操作逻辑”，开启后全部 V 工具采用新操作。可自定义快捷键控制同一选项，默认不绑定，输入文字时不触发。该选项注册于 `folkways_core` 的 CLIENT 配置，保存在本地 `config/folkways_core-client.toml` 的 `book.globalTacticalControlUsers`，按启动账号 UUID 分别记录；不写入殖民地、世界或服务器配置。未列出的账号默认关闭，切换聚落不会改变偏好。

`Pages.open(page)` 通过客户端桥请求声明的主书页，服务端重新检查手持书、当前聚落及管理权限，并拒绝未知或隐藏页面。`Overhead.camera()` 仅提供客户端相机观测，不增加居民控制权或命令执行入口。

### War：屏幕框选、快捷编队与鼠标命令

可选 folkways_war 只提供输入与显示。Core 提供通用 OverheadTools.Handler 和 Overhead.screenRay()；Vanilla 的 CombatPackets、SelectionOrders、CombatSelectionOwnership 与 UnitGroups 管理鉴权、居民控制权和实际命令，War 不直接控制导航。

| 操作           | 结果                                                         |
| -------------- | ------------------------------------------------------------ |
| 左键拖动／单击 | 用当前聚落可用居民替换可见选区                               |
| Shift＋左键    | 框选追加成员；单击切换该成员是否选中；按下鼠标时锁存增选意图 |
| Ctrl＋1～9     | 用精确选区替换该快捷组；与原组完全相同时解散该组并保留选区   |
| 1～9           | 选回服务端当前保存的快捷组；支持主键盘和小键盘数字           |
| 右键地面       | 立即替换全部路线，以点击处为逻辑队长目的地                   |
| 右键非友方生物 | 下达原生明确攻击；不包含居民、友方或玩家                     |
| Ctrl＋右键     | 每点击立即执行或追加一个必经点；重访旧点形成循环巡逻         |
| Esc／空地左键  | 清除可见选区；已无选区时 Esc 可退出俯视界面                  |

快捷组可以重叠；同一居民同时只由一个玩家持有，只执行一套实际小队命令。Vanilla 在服务端保存每玩家选区和九个快捷组。居民只要仍在选区或任意快捷组中，就不参与普通劳动分派。每名居民单独按引用并集判断：ABC 改成 AB 后，C 没有其他引用才释放；同集合 Ctrl＋1 只清快捷组，ABC 仍被框选，不能返岗。

选择指针手势通过 Handler.blocksCameraDescent() 暂停相机下降；Shift 增选意图在左键按下时锁存，提前松开 Shift 不会把追加变成替换。未进行选择手势时，纯 Shift 仍使相机下降；中键平移与 Alt＋中键旋转保留原有手势所有权。

Core 的被动 Urge.reserve 从劳动调查中移除受控居民，并通过原 BodyRunner 正常收尾已有普通图劳动，工具材料沿原结算流程归还。保留本身不创建目的地、队形或导航所有者；生理、恐惧和自主战斗仍可使用同一个执行器。Vanilla 仅跟踪该控制会话实际发出的小队命令 generation，覆盖移动、攻击、停止及其重组待命；最后引用移除时释放对应旧控制，不取消后来的替换命令或书页部署。

关闭 V 或切换工具只清可见选区，有快捷组者仍保留控制和命令，并在界面外继续每 40 tick 续租；租约为 100 tick。心跳不阻止已确认选区下令。失权、换 realm、断线、死亡、卸载及租约过期清理受影响成员。快捷组目前尚未持久化。

Ctrl 每个点击都立即下达。A→B→C→D→B 先经过 A，再循环 B→C→D→B。开放路线到末点后，全队集合并停留 20 tick，继续受控等待；之后追加不会重走前缀或重复已完成的停留。仍有效的普通单点 A 可用 Ctrl 点 B 扩成队列。闭环后的编辑暂时冻结，继续 Ctrl 点击会明确提示先用右键重设路线；普通右键始终替换整个旧路线。

路径标记仅来自服务端已接受快照。重新框选或召回快捷组会恢复对应完整实际小队的路线；替换命令被拒绝时保留并返回旧路线。控制操作和移动命令具有单调请求序号，客户端丢弃旧回复；战斗专用网络协议为版本 5，客户端与服务端必须一致。进度观察包含命令 generation、当前停点、完成状态及待归队人数，客户端只把匹配 generation 的进度应用于已确认路线。

PointRoute 不生成额外队长实体。第九批把途中凝聚与到站集合分开：从同一真实参考居民及导航实时游标截取累计最多 6 格的可用路径前缀，允许有用的部分路径；参考居民距进度锚点两格、其他成员距各自站位三格以内即可继续行进。到达玩家指定点时，仍要求参考成员经过该点、全员进入既有 Reach 容差并持续停留 20 tick。每路段最多 2400 个有效行军 tick，交战、恐惧、全队未加载和到站驻留不消耗预算。

站位沿用成员相对偏移，检查真实体积不重叠；只在规划或恢复批次探测可达性，每成员最多 12 个候选。短暂无路跨 tick 重试三批，分别退避 10／20 tick。成员连续 100 个有效 tick 未改善至少半格时，最多尝试两次重寻／换槽。耗尽后保控等待，分别报告无路、成员受阻或行军超时及待归队人数，不跳过必经点、传送或自动返岗。这仍是有界恢复，未宣称通用窄路可靠性或大规模寻路性能已经验证。

Core 的 `Urge.Priority.CONTROL` 将玩家控制与普通需求的数值权重分开，移动、驻守、撤退与明确攻击不再排在劳动或高权重个人需求之后。仍由同一 BodyRunner 安全交接，原工具及材料沿原流程结算。新点巡逻的到站 GUARD 以 `Order.deliberateGuard()` 保持控制优先，实际交战或低血遇险时才借出执行器；旧自主 guard 规则不变。扩展的真实硬直或生命周期锁仍然有效。

左侧输入提示通过 `Handler.cues()` 显示当前工具的实际操作，战斗下不再显示登记／移出、打开书页或旧旋转说明。`bottomInset()` 为底部兵牌预留空间，提示从顶部按钮下方排布。底部显示 1～9 编队卡和当前选中居民的头像、血条及分页；点击编队卡选回，Ctrl＋点击保存，数字键对应相同操作。头像使用居民外观声明的皮肤或模型回退皮肤，不重复渲染每个三维实体。Tab 按“点选→圈地→画线→扩展工具→点选”循环，切换时清除未完成的图形草稿。

明确攻击通过同一执行器接近目标并使用真实 `WeaponSession`，持续重验指挥者权限、目标身份、友方关系、距离与生存状态；600 tick、起点 64 格及指挥者／居民距目标 128 格的边界限制追击。`WeaponSession.explicitTarget(target, authorized)` 为扩展提供单目标、实时可撤回的授权，默认拒绝；扩展必须明确实现，不能将一次许可推广到其他目标。原版中立及巡逻自主索敌规则不变。本增量不开放玩家 PvP。

客户端居民身份通过服务端按当前持书权限返回的名单确认，不读取未同步的 Body 附件猜测归属。命令包含明确的聚落 ID、居民 UUID 和 WorldPos。服务端重新检查所有成员、全部路线点及最终阵位后才接管；无效命令不会部分迁移成员。选中者可以来自多个实际队伍，未选者保留原队伍与命令意图，旧句柄不能取消新命令。一次提交的安全上限为 256 人、16 个路线点，超限整次拒绝，绝不截取前 8 人；这不是 256 人性能或复杂地形通过保证。

本轮快速迭代先编译全部模组与 GameTest 源码，再替换日常实例供人工测试。编队、控制权、攻击收尾、失败待命和战后续路的 GameTest 源码必须区分“已编译”与“已运行”。更新 PR 前再运行 GameTests 与 Blockwright，覆盖屏幕框选、快捷键冲突、闭环路径、窄路、死亡／卸载和存档重载。

### RTS 设计审计与下一阶段

后续涉及 RTS 操作、命令语义、选区、快捷组、编队、队列或战斗界面的设计改动，先交独立 RTS 设计专家审计；本对话复用 rts_design_auditor，其他会话恢复同一专家角色。审计记录规则、输入冲突、服务器权威、结束条件和验收场景；设计审查与工程验证分别报告。

第八批落实以下已审规则；静态设计通过不代表运行时验收：

- 完整选中同一实际小队时，指定攻击保留小队 ID；部分或跨队选区建立一个新小队，未选成员保留旧意图。新攻击替换旧路线。目标死亡、消失、失去敌意、越界或超时后结束追击，在幸存者附近重组，全部到位且无交战／恐惧借用达 20 tick 后驻守待命。
- 重组无安全锚点、成员执行失败或有效移动耗尽 1200 tick 时进入 FAILED_WAITING，保留控制和可读原因，不再追击、推进路线或恢复旧巡逻主动索敌／补给。仍允许真实攻击者触发的有限自卫及恐惧。没有幸存者不得报告成功；新命令可以立即替换等待。
- “攻击前进”按钮为下一条新地面路线启用一次迎敌策略，服务端接受后解除武装；拒绝保留按钮状态，清选区或退出工具清除。每条路线固定普通移动或攻击前进，Ctrl 追加继承其策略。已确认的普通路线不能通过一次 Ctrl 追加静默变更，需普通右键建立新路线。替换回复在途时的后续点击依据新路线意图排入待发送输入；不绘制未确认路径草稿。
- 攻击前进只自动迎击既有敌意生物，目标和可达战位受战前阵位 12 格范围约束。交战保持逻辑队长及当前未完成路径点，结束后回原阵位稳定 20 tick，再继续路线；指定路径点仍必须经过并停留 20 tick。普通地面移动继续优先赶路。
- “停止”立即取消路线和追击，在附近重组并保留控制，只作有限自卫；没有安全锚点也接受停止并显示失败待命。“解除控制”在服务端原子移除所选居民在当前选择及全部九个快捷组中的引用，再释放本会话控制，未选成员不变。
- 底部按钮及状态条分别显示服务端接受、当前命令、行进／交战／重组／等待和结束原因。停止与解除均等待实际确认；状态标识在客户端翻译。保留中键平移、Alt＋中键旋转及现有个人设置，不占用 WASD、Shift 或 Tab 新快捷键。

第九批根据实机反馈补齐以下规则；这些变化仍需人工与 PR 前运行时回归：

- 普通右键移动和点队列都从当前队伍观察中心画向正在执行的目标，显示剩余命令意图，不冒充实际导航绕行路径。已执行前缀隐藏；循环保留循环段。开放末点完成全员到站及 20 tick 驻留后隐藏完成线，但服务端历史、控制权和继续 Ctrl 追加／闭环能力保留。按住 Ctrl 时可临时回看已确认历史的淡色标记来闭环，松开恢复剩余段；只有实际显示的已确认标记参与像素吸附，未确认输入不画草稿也不作不可见吸附。
- 战斗底栏目标压到 48～64 个界面单位，缩小装饰和重复文字；九个快捷组、三个命令按钮及失败原因仍可访问。左侧只常驻核心提示，其余放悬停帮助；其他工具保留旧提示。选中世界居民只显示轻量短血条，每帧仅投影一个头顶点；框选命中投影在输入事件中计算，拖动只绘制一个选择矩形。未测量实际 FPS，不把截图中的卡顿归因于单一绘制步骤。
- 选区、任意快捷组引用或有效手动命令均推迟睡眠，包括失败待命；撤下睡眠 Urge 使原执行器安全结束已有躺卧。最后控制引用和手动命令解除后恢复睡眠，恐惧、战斗与进食仍保留其原规则。
- Vanilla 时间疲劳改为所有已加载居民的实际清醒时钟，普通闲站也会疲倦；每 30 tick 增加一点基础疲劳，一 MC 天达到原困倦阈值 800，并受 FATIGUE 效果调整。劳动结算不再重复计 activeTicks 的时间疲劳，实际步行距离和原饥饿耗能照旧。睡眠、缺失 tick、离线及重载首个观察不补扣；旧 Tired 数值存档继续兼容。休息不足仍沿用心情 −5／−10，没有第二层熬夜数值惩罚。

后续继续验证窄路、台阶、重组与实际掉队恢复，再推进完整兵牌、持久化和规模性能。先验证 16～32 名居民加对等敌人，256 仅是报文安全上限。个人相机设置和非战斗工具操作保持原契约。

## P4：实际原版武器会话

`plugins.combat.weapon` 公开 `WeaponAdapter`、`WeaponSession` 和 `Weapons`。`Weapons.register(id, adapter)` 在模组初始化时注册独立适配器、拒绝重复 ID；默认提供真实近战、弓和弩实现，没有枪械桩。

| API／状态                | 实际行为                                                                          |
| ------------------------ | --------------------------------------------------------------------------------- |
| accepts／usable／range   | 识别物品、真实弹药或已装填弩，以及有效射程；无弹远程武器可退选库存中的剑          |
| open                     | 从真实 Pack 移出唯一物品到独占主手，不复制装备；由当前劳动节点取得并推进          |
| READY／FIRING／RELOADING | tick 驱动近战挥击、拉弓、弩原生装填与发射，每次执行检查敌意、视线、距离与生命周期 |
| stop／STOPPING           | 终止新射击、清除蓄力；原版停止无需异步等待，不调用会误射箭的 releaseUsingItem     |
| close／CLOSED            | 幂等归还真实装备；背包满时仅掉落一次                                              |

工作展示副本与真实主手会话分开管理。弓复用原版 ProjectileWeaponItem 的 draw/shoot；弩复用原生 releaseUsing/performShooting，真实消耗箭、保存装填组件与修改耐久。Native 会话的 stop 是终止操作，继续射击须取得新会话；已发出的投射物继续按原版飞行。

Entity 在 addAdditionalSaveData 前序列化附件，因此 ResidentEntity 在 saveWithoutId 入口先停止并归还武器，保证 Pack 快照仅拥有一份。卸载、离籍、死亡及聚落撤销均终止会话；弩已装弹组件随真实物品保存。

原生持械会话目前支持 ResidentEntity。其他 ResidentKind 保留原有 ToolUse 近战及已声明的裸手战斗，不因携带剑或弓而失去原有攻击；真实持械会话需所属扩展接入。TaCZ、Point Blank 与异步持续枪械动作仍需各模块实际适配与验证。衣甲仍由 Core Equipment 管理。

### 有限巡逻补给

`PatrolSupplies.of(colony)` 提供 `loadout(body, Loadout)`、`clear(body)`、`preference(id)` 与 `status(id)`。显式偏好优先选择已携带且可用的相应真实武器；缺失或不可用时沿用原有回退策略。改变偏好会安全关闭当前原生会话，再允许新选择射击。

守卫和当班巡逻员最多补一把指定武器与八支箭，已装入弩的弹药也计入。已有弓弩可直接推断弹药补充，无须新设偏好。补给 Urge 让位于战斗、恐惧及撤退，实际走到 32 格内的登记仓库，在领取时重查访问规则、库存预留、真实容量与现货。全程沿用同一个 BodyRunner 和 Staged 结算并保留物品组件。单次行程上限 200 tick；缺货和满背包有可查询状态及有限退避重试，新命令撤销旧补给请求。PackKeeps 让有限装备在普通返存时继续由居民保管。

补给目标不会移除玩家原先给予的其他武器。第三方库存适配器在修改后抛错时，需要可读取同组件物品数量才能回滚；任意不可读或受外部异步修改的库存不属于已验证兼容范围。

弓弩通过通用 `CoreSettings.defaultTool(ItemSpec)` 声明默认许可，不加入每名巡逻员必备的职业工具。已保存的聚落工具列表继续有效；旧聚落需要在生产设置中允许弓弩，仓库还需有相应现货。

Core 的声明期扩展 `KitRules.supplyPolicy(owner, policy)` 只决定普通自动装备配送能否参与。Vanilla 在手动命令或真实武器借用期间让这类配送暂停；原有请求通过正常撤销流程交还预留，控制解除后恢复。Survey 观察策略变化，即使背包未变也重新读取装备需求。该策略不改变工具保留，也不跳过其他任务的库存预留。
