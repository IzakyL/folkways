# 殖民地袭击

[架构说明](architecture.md) · [English](../en/raids.md)

在 Core 和 Vanilla 旁安装可选模组 `folkways_war`。War 负责殖民地袭击，Vanilla 继续负责敌意、警卫、队形、指令和有限武器补给，无需额外战斗模组。

## 玩法

所有殖民地默认开启袭击，包括已有存档。首次安装 War 后，每片殖民地都获得完整的七天宽限期。只有至少四名居民且附近有在线成员时，模拟时间才会累计。袭击结束后，间隔五至八个模拟日恢复资格。自动袭击在黄昏预警，两分钟后进攻。和平难度、`disableRaids`、`doMobSpawning=false` 和禁用维度会阻止开始；默认禁用末地。

殖民书的「袭击」页显示倒计时、来袭方向、波次、剩余敌军、最近一次损伤和劫掠战报，并提供殖民地开关。每次读取和修改都会重新验证成员权限。服务器袭击条和聊天预警跟随在线成员，重新连接后会同步当前袭击条。警卫仍在「战斗」页部署；War 不覆盖玩家指令，也不增加另一套居民控制系统。

默认三波敌军包含僵尸、骷髅、掠夺者、卫道士、苦力怕和劫掠兽，也支持女巫。居民数量、模拟年龄和困难难度会增加人数，默认强度上限为三。War 将主动居民目标限定为被袭击的殖民地，战斗由生物自身的 AI 执行。这些敌军不会加入村庄袭击。

出生点在殖民地附近设施范围之外，排除玩家近身、其他殖民地、液体、危险地面和不能模拟的区块，并验证抵达外围进攻位置的路线。路线和远处孤立设施不会扩大进攻区域。没有合格位置就延后。船只等结构空间中的殖民地暂缓袭击：当前版本不能验证登船路线，不会在甲板或船只存储坐标生成敌军。

附近没有在线成员时，袭击计时和敌军 AI 暂停。缺失的 UUID 保持未决，不算击杀，也不会补刷。清除所有波次获胜。居民全部死亡，或敌军占据无人防守的登记仓库十秒后，进入失败劫掠。普通袭击超过二十个模拟分钟会撤退。关闭或搬迁殖民地会取消袭击，服务器关闭则保留进度。

## 建筑、火灾与劫掠

破墙和爆炸共用每场默认 96 个方块的额度。破墙者持续敲击后可拆除普通石头、石砖和深板岩，默认硬度上限为五；直接破墙不碰方块实体。黑曜石、不可破坏方块及 `folkways:raid_protected` 方块标签受到保护，标签包含 TNT、床和重生锚，防止额外连锁破坏。苦力怕保留自身爆炸和容器掉落行为，但实际受袭击额度过滤。劫掠兽破坏树叶和踩坏耕地也消耗同一额度。门的两格都必须通过授权并消耗额度。生物自身的破门与毁蛋目标不能绕过检查。敌军弹射物引起的方块变化也经过权限和额度检查，燃烧箭不能点燃受保护的 TNT。

纵火者挥手并播放打火石声音，生成真实 `Blocks.FIRE`。默认每波最多十二个火源，每名纵火者最多三个；每场最多蔓延至 192 个空位、烧毁 96 个方块，这些是独立额度。火焰 Mixin 保留原有燃烧算法，在每个有来源的蔓延或燃烧目标发生变化前检查，也在 `onCaughtFire` 之前检查。来源和剩余额度在敌军死亡、袭击结束、殖民地关闭和服务器重启后保留。灭火立即移除该位置的来源记录。玩家点燃且没有袭击来源的火焰维持通常行为。

所有破坏路径都经 `WarEdits` 检查 `mobGriefing` 和 NeoForge 事件，火焰另检查 `doFireTick`。关闭相应规则会停止后续袭击火灾破坏。破坏事件使用独立的匿名敌军身份，实体破坏和放置事件保留敌军来源。当前基础分支没有 FTB Chunks 桥；未来保护桥应接在这一个权限入口，并覆盖余火。损控无需依赖 War 类：真实火焰和缺块可直接被扫描。

失败时只生成有限劫掠清单，不直接扣除库存。敌军必须走到登记仓库，在可触及、可看见的位置花时间取货，携带真实移出的物品后逃离。默认取每个选中物品堆数量的两成，向下取整、至少一件；每场最多八堆、256 件，每名携带者最多两堆。`raid_precious` 和 `raid_valuable` 物品标签决定贵重物资的优先级。取货、携带、重载和死亡掉落保留物品组件。击杀携带者可以回收赃物，战报区分被取走物资与可回收掉落物。逃走的赃物算作损失；管理员取消时，已加载敌军会掉落赃物。

执行取货时重新检查禁止取货规则、槽位限制和容器锁，大箱子的两半都必须未上锁。仅允许维度空间中已登记的 `BaseContainerBlockEntity` 仓库；没有已知安全接口的机器库存暂不纳入。劫掠限时一分钟，同一清单项不会重复扣货。袭击不会删除殖民地，也不额外生成胜利奖励。

## 配置与数据包

服务器配置文件为 `folkways_war-server.toml`，包含总开关、宽限期、居民门槛、间隔、预警与超时、禁用维度、同时袭击与敌军上限、强度、破坏、火源、蔓延、燃烧、仓库占据时间和劫掠额度。殖民地开关独立保存，服务器上限优先于定义上限。

定义位于 `data/<namespace>/raid/*.json`，内置文件为 `data/folkways/raid/siege.json`，`schemaVersion` 为 `1`。每个 `waves` 项包含 `delayTicks` 和 `entries`；敌军项包含 `entity`、`role`（`fighter`、`breacher`、`arsonist`）、`count` 和可选的装备槽位到物品 ID 映射。支持名单排除首领与唤魔者，召唤物需要先补全归属记录。重载时拒绝未知实体、角色、装备、版本和越界数量。

可选 `limits` 对象支持 `brokenBlocks`、`hardness`、`fireSourcesPerWave`、`fireSourcesPerRaider`、`fireSpreadBlocks`、`burnedBlocks`、`plunderShare`、`plunderStacks`、`plunderItems` 和 `plunderStacksPerRaider`。缺省使用内置值。活动袭击保存已解析、已缩放的定义快照，`/reload` 只影响之后的袭击。装备使用真实物品 ID，不增加另一套武器实现。

权限等级至少为二的管理员可使用：

```text
/folkways raids start <colony-uuid> [definition-id]
/folkways raids stop <colony-uuid>
/folkways raids status <colony-uuid>
```

开始命令仍检查游戏规则、额度和城外出生点。省略定义 ID 时使用按 ID 排序后的首项。没有可供普通玩家绕过冷却的主动开战操作。

`colony.keep(folkways:raids)` 保存第一版格式，包括开关、模拟年龄与冷却、袭击身份、目标 `WorldPos`、种子、波次槽位与实体 UUID、损伤计数、仓库占据进度及劫掠清单。旧存档没有插件数据时，显式初始化为开启并给予完整宽限期；加载第一阶段的旧数据时，新增计数与清单按零或空值处理。火焰采用各维度独立的第一版 `folkways_raid_fires` SavedData，关闭殖民地不会清除余火保护。服务器关闭保留两份记录，UUID 重新关联不会通过补刷填充缺失槽位。

## 验证

```sh
./gradlew build
./gradlew runGameTestServer
./gradlew -PwarTests=true -PgameTestMod=war runGameTestServer
./gradlew -PwarTests=true runGameTestServer
npm run test:i18n
```

War 测试显式推进殖民地模拟，使用固定袭击种子并隔离游戏规则变化，覆盖真实战斗伤害、现有警卫执行器、波次、缺失与重载敌军、实际破墙、爆炸额度、火焰来源和燃烧额度、真实劫掠和死亡掉落、容器锁、跨殖民地目标及成员权限撤销。客户端渲染、真实进程重启、FTB 保护、登船和第三方敌军池不属于这些 GameTest 的覆盖范围。
