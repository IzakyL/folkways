# 扁平化资源

[文档](README.md) · [English](../en/resources.md)

在 Core 和 Vanilla 之外安装 `folkways_resources` 即可启用扁平化资源。
扩展在 `folkways` 命名空间新增四种可堆叠的资源物品，原有方块和物品继续保留。

| 资源     | 默认配方原料（每份一件）                                                     | 工作时的替代范围（每件消耗一份资源） |
| -------- | ---------------------------------------------------------------------------- | ------------------------------------ |
| 木材资源 | 任意原木                                                                     | 原木、木板及标签中的木制建筑构件     |
| 石材资源 | 石头、圆石、安山岩、闪长岩、花岗岩、深板岩、深板岩圆石、黑石、凝灰岩或方解石 | 标签中的石材和石制建筑构件           |
| 树苗资源 | 标签中的任意树苗                                                             | 标签中的任意树苗                     |
| 种子资源 | 标签中的种子                                                                 | 标签中的种子、胡萝卜和马铃薯         |

居民直接把资源运到工地、填地区域或农田并在当地消耗。蓝图仍然放置已经确定的准确方块状态，
农田仍然种植选定的作物或树苗。机械动力的蓝图放置适配器以及通过 `BlockItem` 放置的
`CropBehavior` 也走相同结算。工作之前不需要在工作台转换成指定材料，也没有资源换回材料的配方。

先预约背包或仓库中相符的材料，再使用背包或仓库中已有的资源，最后考虑正常生产原材料。
每组内部继续沿用现有搬运和来源排序。玩家可以手工合成资源，居民也可以通过已有加工工作台和
库存订单按普通配方生产资源。JEI 和 EMI 自动显示这些配方。

殖民书的“资源”页显示当前维度殖民地仓库中的资源实物库存、各分类的替代范围和消耗比例。
同一份资源不会按每种可替代品种分别累加。种子资源没有食物组件、堆肥值或种子标签，也不加入
按作物划分的 `SeedReserves` 分组。

## 数据包

覆盖 `data/folkways/resource_categories/wood.json` 可以修改或停用分类：

```json
{
  "resource": "folkways:wood_resource",
  "members": "folkways:flattening/wood/targets",
  "default_item": "minecraft:oak_planks",
  "cost": 1,
  "enabled": true
}
```

`members` 是物品标签 ID，不带 `#`。`cost` 是从 1 到 64 的整数，表示每件所需材料消耗的资源数量，
默认值为一。具体物品需求保留自己的品种；宽泛标签或多选需求在允许时选用分类的 `default_item`，
否则选择满足需求的代表物品。资源只代付默认组件身份的材料；带自定义名称、内容物或其他特殊组件的
目标仍然需要相应实物。

扩充 `tags/item/flattening/<category>/targets.json` 可以修改替代范围，扩充 `sources.json`
可以修改兑换原料。内置目标标签引用 Minecraft 的原木、木板、木制构件和树苗标签，以及通用石材、
种子标签，兼容模组的物品会通过这些标签加入。其他石制构件也可逐项添加。
覆盖 `recipe/flattening/` 下的普通配方可以修改产出数量或损耗。
新分类文件可以使用任何已注册物品作为支付物；新增物品 ID 仍然需要模组注册。

木材配方默认只收原木。木板和木制成品可以被替代，但不能默认作为兑换原料；石材配方也排除了
楼梯、台阶和墙。因此，放置并回收一根原木只会消耗和返还一份原料，把原木加工成多块木板不会
增加资源。资源配方不附带制作特长的返料或副产物规则。
数据包扩充兑换原料或增加奖励时，需要自行平衡可能形成的循环。

普通 wares 配方输入仍然要求实物。若允许一份资源在木板配方中充当原木，就会产出多块木板，
重新形成资源增殖途径。装备、口粮、配送、堆肥和库存订单交付也继续按实物身份处理。

## API 与存档

Core 提供通用的 `InputSubstitutions`、`InputAllocation` 和 `InputReceipt`。
消费者通过 `Need.replacing()` 明确启用代付。`Goods` 和普通库存匹配保留物品及组件身份。
Weaver 按比例预约并搬运实际支付物；Commit 在提交期间向现有消费者提供所需输入，
并通过 `Outcome.Done.inputs()` 同时记录所需材料和实际消耗物。
未使用、失败和异常时返还实际支付物；已搬运工作的取消继续走现有携货回收流程。
一份实物资源不能同时支付多个竞争需求。

供料检查和实际扣料共用按完整物品身份分组的分配逻辑，少量命名资源不会遮住足量普通资源。
每次实际抽取都会先登记，再继续处理下一槽或调用容器回调。抽料失败时返还全部实物；
输出槽禁止回填时，依次退入居民背包或掉落。

重载时把不可变规则与版本一起原子替换。每轮规划固定使用同一快照，发布前持有重载锁复核版本；
失效轮次释放新增预留后重新规划。尚未开始的工作会重新计算；已开始工作的预留在搬运后仍保留
原需求和比例，因此代付失效时会报缺料，不会取用另一项工作的材料。扣料前也会检查当前规则。
扩展没有新增保存设置，也没有修改已保存工作的格式；旧殖民地、
蓝图和农田无需迁移即可加载。不安装扩展时，不会注册资源物品或代付规则，现有工作继续使用实物材料。

四张透明的 16 × 16 PNG 位于
`mods/resources/src/main/resources/assets/folkways/textures/item/`，
由内置 imagegen 工具生成并以最近邻采样导出为物品纹理尺寸。
生成提示保存在 `mods/resources/art/prompts.json`。

## 验证

多任务共用机器时，所有 Gradle 命令都加上 `--no-daemon`：

```sh
./gradlew --no-daemon build
./gradlew --no-daemon runGameTestServer
./gradlew --no-daemon -PresourcesTests=true runGameTestServer
./gradlew --no-daemon -PresourcesTests=true -PgameTestMod=resources runGameTestServer
npm run test:i18n
```

Blockwright 的 `resources` profile 在基础配置固定的依赖之外安装可选资源扩展。
消费者测试位于 Vanilla 的 `src/resourcesTest`，建造、种植和填地的包内场景仍归所属 Java 模块。
资源模组负责配方、物品身份与携货回收测试，Core 负责通用分配和预约测试。
